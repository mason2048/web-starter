# web-starter V2 验收基线

> 状态：**已冻结，进入开发与验收**
> 产品：启程 Web Starter
> 版本：`2.0.0`
> V1 来源：本地 tag `v1.0.0`，commit `5ebdb238650d182c17e1493adf47aaa3324f19cb`
> 基线日期：2026-07-19

本文是 V2 的开发、回归和发布目标。任何 P0/P1 的删除、降级或用较弱证据替代，都必须先更新本文并重新确认。

## 1. 发布目标

从可追溯的 V1 发布基线出发，将启程 Web Starter 升级为可安全生成派生项目和业务模块、可从 V1 无损升级、可观测、可恢复、可持续发布的内部管理系统脚手架；完善身份与凭据生命周期、MCP 写操作幂等和会话治理，并通过真实 MySQL、Redis、浏览器、OAuth 及官方 MCP SDK 完成全栈验收。

编译成功、单元测试通过、镜像构建成功、容器显示 healthy、健康检查 200、页面可打开或静态扫描零命中，都不能单独证明 V2 完成。

## 2. 固定边界

- Java 21 是构建产物和部署运行时基线；Spring Boot 4.1 与 Spring Security 7 是唯一后端安全基础。
- 继续采用模块化单体；REST 与 MCP 必须共用 Caller、实时 RBAC、Scope、业务 Service、事务和审计。
- MySQL 是业务、安全凭据元数据和审计事实来源；Redis 只保存 Session、短期协调和可重建数据。
- Flyway 迁移只追加；V2 必须同时支持空库安装和从 `v1.0.0` 数据升级。
- 项目与模块生成器是离线开发工具，只写入用户明确指定的输出目录，不通过 Web、REST 或 MCP 暴露。
- V1 的 REST 路径、权限编码和七个 MCP Tool 名称继续兼容；新增字段优先采用向后兼容方式。
- 外部 MCP 继续使用 OAuth；PAT 和服务账号长期令牌只允许受控私有入口。
- 不加入公网自助注册、SaaS 多租户、套餐计费、微服务、服务发现、分布式事务、MCP Client、工具市场或聊天页面。
- 不提供任意 SQL、Shell、进程、文件系统、动态代码执行或第三方 MCP 代理能力。
- 不内置第二个正式业务示例、工作流引擎、通用审批、文件中心或运行时低代码平台。

## 3. 证据与级别

| 级别 | 定义 | 发布处理 |
|---|---|---|
| P0 | 数据、安全、兼容性、核心生成能力或发布链路 | 任一失败即禁止判定 V2 完成 |
| P1 | 可运维性、管理体验、异常路径和工程完整性 | 任一失败原则上阻断，除非用户书面接受 |
| P2 | 可选增强或具体部署方策略 | 可以进入后续版本，不得冒充 V2 已实现 |

每项结果只能记录为：`PASS`、`FAIL`、`NOT_COVERED` 或 `ENV_REQUIRED`。后两者都不等于通过。仓库发布验收和真实目标环境验收必须分开记录。

正式执行时使用 [V2 验收证据模板](./v2-evidence-template.md) 建立 45 项账本；模板中的默认 `NOT_COVERED` 不得由构建或静态检查自动提升。

### 4.4 身份与凭据生命周期

| ID | 级别 | 验收域 | 可执行通过标准 |
|---|---|---|---|
| V2-AC-23 | P0 | 个人安全 | 用户验证当前密码后修改本人密码，可查看活动 Session、撤销指定 Session 或退出其他设备，不能自行提升权限 |
| V2-AC-24 | P0 | 级联失效 | 密码重置、用户停用/删除或安全注销后，相关 Session、OAuth access/refresh token 和策略指定的 PAT 下一请求失效 |
| V2-AC-25 | P0 | 登录防护 | 登录按账号与来源地址组合限速并渐进退避；不泄露账号存在性，不因单一来源阻断其他正常账号 |
| V2-AC-26 | P0 | JWKS 轮换 | 支持 active/retiring 多 `kid`；新 Token 使用新键，旧 Token 在保留窗口内可验证，窗口结束或紧急撤销后被拒绝 |
| V2-AC-27 | P0 | Pepper 轮换 | 长期令牌哈希记录密钥版本；旧版本令牌在验证成功时可迁移到活动版本，数据库和日志不出现明文 |
| V2-AC-28 | P0 | Client 密钥轮换 | OAuth Client Secret 支持有限重叠窗口；窗口内新旧密钥按策略工作，结束后旧密钥拒绝并有审计 |
| V2-AC-29 | P0 | Production fail-fast | 生产模式遇到 HTTP/localhost Issuer、非 Secure Cookie、开发 RSA、空/占位秘密、宽泛 Host/Origin 或危险日志级别时拒绝启动 |
| V2-AC-30 | P1 | 凭据管理 | 私有管理端可筛选即将过期、长期未使用、已吊销和受 IP 限制的凭据；一次性秘密仍不可再次读取 |

### 4.5 MCP 幂等与会话治理

| ID | 级别 | 验收域 | 可执行通过标准 |
|---|---|---|---|
| V2-AC-31 | P0 | 写操作幂等 | V2 Agent 为 create/update/remove 提供幂等键；同一 Caller、Tool、键和参数的并发/重试只提交一次并返回稳定结果 |
| V2-AC-32 | P0 | 幂等冲突 | 相同幂等键配不同参数返回结构化冲突；幂等记录不保存明文 Token 或非必要业务敏感内容，并按期限清理 |
| V2-AC-33 | P0 | Tool 契约 | 写 Tool 提供明确输出 Schema、稳定错误码和风险 annotation；旧客户端调用路径有兼容或明确迁移证据 |
| V2-AC-34 | P0 | Session 生命周期 | MCP Session 有空闲 TTL、绝对 TTL、每主体上限、显式 DELETE 和优雅停机清理；过期 Session 不能继续调用 |
| V2-AC-35 | P0 | 应用级限流 | 在 Nginx IP 限流之外按主体、Client 和 Tool 风险级别限流，429 提供 `Retry-After`，限流结果进入 MCP 审计 |
| V2-AC-36 | P0 | 统一安全回归 | RBAC 与 Scope 交集、主体禁用、凭据吊销、Host/Origin、内外网令牌边界和审计继续通过 V1 全部相关负向用例 |

## 5. V1 回归门禁

V2 发布前必须重新执行 [V1 验收基线](./v1-acceptance-baseline.md) 的 42 项。允许证据实现方式升级，但不得降低权限、事务、审计、内外网入口和禁止工具边界。

七个既有 MCP Tool 名称保持：

- `system.info`
- `project.list`
- `project.get`
- `project.create`
- `project.update`
- `project.remove`
- `audit.list`

模块生成器新增的 MCP Tool 只能存在于生成后的派生项目或临时验收副本；正式模板仓库的默认清单不因演练而扩张。

## 6. 仓库发布与目标环境的证据边界

V2 仓库发布可以证明：空库和 V1 快照升级、真实 Compose、浏览器、OAuth、MCP、入口隔离、恢复机制、镜像硬化和当前漏洞库门禁。

具体部署方仍需单独记录为 `ENV_REQUIRED`，不得由本地 Compose 代替：

- 正式 DNS、CA 证书、证书续期、防火墙、负载均衡与可信代理链；
- 组织的密钥托管、集中日志、指标采集、告警路由和访问审批；
- 真实备份介质、异地保留策略、RPO/RTO 与恢复责任人；
- 真实用户 Agent、自动化 Agent、参考硬件容量、并发、时延与稳定性。

这些环境项不阻止通用脚手架形成 V2 仓库发布，但没有完成时不得声称具体环境已经生产就绪。

## 7. 开发顺序

1. 固定 V1 tag、V2 契约、兼容清单和升级数据准备方式。
2. 先把真实 Compose、浏览器、OAuth 与 MCP 验收固化成可重复工具。
3. 实现项目初始化器、模块生成器和统一开发命令。
4. 实现身份/凭据生命周期、MCP 幂等与 Session 治理。
5. 实现可观测、恢复、生产配置和供应链门禁。
6. 同时执行空库与 V1→V2 升级，完成 V1 全量回归和 V2 逐项验收。

## 8. 变更控制

- P0/P1 的删除、降级或改写必须由用户确认。
- 新增依赖必须先验证 Java 21、Spring Boot 4.1、Spring Security 7 和许可证兼容性。
- Flyway 已发布迁移不得修改；V2 从新版本迁移开始演进。
- 生成器、恢复脚本和 CI 不得输出或保留密码、Cookie、Token、PKCE verifier、Client Secret、Pepper 或私钥。
- 遇到实现困难时修正实现或明确记录 `NOT_COVERED`，不能把构建、Mock 或静态检查替代真实运行证据。
