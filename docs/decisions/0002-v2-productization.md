# ADR-0002：V2 工程产品化与生产可控基线

- 状态：已接受
- 日期：2026-07-19
- 来源版本：`v1.0.0`

## 决定

1. V2 不扩张为大而全后台，而是提升派生效率、升级兼容、安全生命周期、MCP 可靠性和可恢复发布能力。
2. 提供离线项目初始化器与模块生成器；它们只操作显式输出目录，不进入 Spring Boot 运行时，也不通过 Web/MCP 暴露。
3. V1 数据库必须可通过追加 Flyway 迁移升级；空库安装与 V1 快照升级是并列发布门禁。
4. V1 REST 路径、权限编码和七个 MCP Tool 名称保持兼容。MCP 写幂等采用显式幂等键并保留旧调用迁移路径。
5. 身份安全增加用户自助改密、Session 管理、级联失效、登录限速、多 `kid` JWKS、Pepper 版本和 Client Secret 重叠轮换。
6. MCP 增加写操作幂等、Session 空闲/绝对期限、主体上限、应用级限流和结构化结果，不改变统一 Caller/RBAC/Scope/审计模型。
7. V2 提供结构化日志、低基数指标、自动恢复演练、SBOM、漏洞门禁和硬化 Compose；不内置完整监控平台或自动部署生产。
8. CI 必须使用真实 MySQL、Redis、构建后的前后端、OAuth 流程和官方 MCP SDK。单元测试或容器健康不能替代全栈证据。

## 原因

- V1 已经证明核心 Web/MCP 安全闭环；继续增加普通页面不会解决复用成本和生产运维风险。
- 受控生成比手工复制更能保护模块边界、权限、迁移和审计契约，同时避免运行时低代码带来的动态执行风险。
- 可追溯 V1 tag、升级测试和发布清单让数据库演进及兼容结论可以复验。
- 幂等、Session 治理和密钥重叠轮换直接降低外部 Agent 重试、资源泄漏和轮换中断风险。
- 结构化观测、恢复演练和供应链证据让“可运行”与“可持续发布”成为不同且可验证的结论。

## 约束

- 初始化器只能写入显式空目录；生成器冲突必须在写入前失败。
- 生成器不下载远程模板、不执行生成结果、不接受可执行模板表达式。
- 生产模式危险配置必须 fail-fast，不能只记录警告后继续启动。
- 指标标签不得包含用户、Token、Client、Trace 或 IP 等高基数/敏感值。
- 数据库迁移不承诺通用向下回滚；采用向前修复或已验证备份恢复。
- 真实 DNS、CA、代理、监控、密钥托管和 RPO/RTO 属于部署环境验收，不得由本地结果冒充。
